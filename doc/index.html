1. 文档概述

1.1. 目的

定义核心分组算法模块的技术接口与数据结构。

1.2. 核心逻辑概述

根据一系列预设规则，将输入的全体参与者（男女）自动分配到若干个固定大小的小组（例如 4 男 4 女）中。分组的优先级依据参与者之间的互选情况、单向选择优先级、以及“媒人”的推荐。

1.3. 接口类型

接口为本地库，非 HTTP 网络接口。

2. 函数接口定义

3. 数据结构

3.1. 输入数据 (Input Data)

3.1.1. `participants` (参与者列表)

用途： 本次匹配的全体人员，是算法的数据基础。

字段名类型是否必需描述
idString是全局唯一的用户 ID。
genderString是性别。推荐值为 "male" 或 "female"。
nameString否姓名。主要用于调试和日志记录，不参与核心逻辑。
 
// JSON 示例
[
  { "id": "m001", "gender": "male", "name": "张三" },
  { "id": "m002", "gender": "male", "name": "李四" },
  { "id": "f101", "gender": "female", "name": "王五" },
  { "id": "f102", "gender": "female", "name": "赵六" }
]

3.1.2. `selections` (用户选择数据)

用途： 描述所有参与者的选择意向和优先级。

字段名类型是否必需描述
(key)String是选择者的 id。
idString是被选择者的 id。
priorityInteger是选择的优先级。数字越小，优先级越高 (例如 1~5)。
 
// JSON 示例
{
  "m001": [
    { "id": "f101", "priority": 1 },
    { "id": "f102", "priority": 2 }
  ],
  "f101": [
    { "id": "m001", "priority": 1 }
  ]
}

3.1.3. `matchmaker_picks` (媒人推荐)

用途： 包含多位“媒人”给出的推荐配对。媒人推荐有冲突时以主媒人为准（待定）。

字段名类型是否必需描述
person1_idString是其中一人的 id。
person2_idString是另一人的 id。
matchmaker_idString是做出推荐的媒人ID (例如 "lead_mk", "assist_A")。
priorityInteger是推荐的优先级。数字越小，优先级越高。
commentString否推荐理由，用于媒人间参考。
 
// JSON 示例
[
  {
    "person1_id": "m007",
    "person2_id": "f101",
    "matchmaker_id": "lead_mk",
    "priority": 0, // 主媒人推荐，最高优先级
    "comment": "主媒人强烈推荐"
  },
  {
    "person1_id": "m007",
    "person2_id": "f105",
    "matchmaker_id": "assist_A",
    "priority": 10, // 副媒人A的推荐
    "comment": "两人是校友"
  }
]

3.1.4. `options` (配置选项)

用途： 传递分组规则等运行时参数。

字段名类型是否必需描述
group_size_maleInteger是每组的目标男性人数。
group_size_femaleInteger是每组的目标女性人数。
previous_groupsArray否（用于多轮匹配） 包含过去已分组配对的 ID 数组，算法应尽力避免这些人再次同组。
 
// JSON 示例
{
  "group_size_male": 4,
  "group_size_female": 4,
  "previous_groups": [
    ["m001", "f108"],
    ["m002", "f106"]
  ]
}

3.2. 输出数据 (Output Data)

`grouping_result` (分组结果)

用途： 函数执行成功后返回的唯一对象，包含所有分组结果和未分配人员。

字段名类型描述
groupsArray<Object>包含所有成功匹配的小组列表。
unassignedArray<Object>包含所有未能进入任何分组的人员列表。
 
// JSON 示例
{
  "groups": [
    {
      "group_id": 1,
      "male_ids": ["m001", "m005", "m008", "m012"],
      "female_ids": ["f101", "f103", "f109", "f111"]
    }
  ],
  "unassigned": [
    { "id": "m025", "gender": "male" },
    { "id": "f131", "gender": "female" }
  ]
}

4. 核心业务逻辑与规则

4.1. 分组优先级顺序

算法在计算匹配权重时，应遵循以下优先级：

  1. 最高优先级：互有好感。 (A 选 B 且 B 选 A)
  2. 次高优先级：单向好感。 (A 选 B，根据 A 设定的 priority 值计算权重)
  3. 普通优先级：媒人推荐。 (根据媒人设定的 priority 值计算权重)

4.2. 媒人推荐处理规则

当多位媒人对同一个人做出不同推荐时，产生冲突。

  • 算法必须优先采纳`priority`值更高（数字更小）的推荐。
  • priority: 0 应被视为一个保留值，专用于主媒人，拥有绝对的、无条件覆盖其他任何推荐的最高权力。（待定）

4.3. 异常与边界情况

  • 剩余人员： 无法满足分组条件（例如 4 男 4 女）的剩余人员，应被全部放入返回结果的 unassigned 列表中。
  • 多轮匹配： 当 options.previous_groups 不为空时，算法应在计算权重时，降低或避免这些已有过交集的配对。
